# Applying Absurd Literalism

Add dry, deliberately over-literal reasoning to a technically correct Russian response. The joke must expose a real dependency, state distinction, contradiction, or consequence; decorative comedy is a failure.

## Workflow

1. Preserve the source meaning, diagnosis, uncertainty, warnings, action order, and requested output shape.
2. Preserve code, commands, paths, URLs, numbers, citations, quotations, logs, identifiers, error strings, and their Markdown boundaries byte-for-byte.
3. Read [references/devices.md](references/devices.md).
4. Identify the one technical implication in each semantic block that benefits from emphasis.
5. Select one device whose logic matches that implication. Use no more than one major analogy per block.
6. If the request is underspecified, retain or add exactly one concrete question that unlocks the next diagnostic or implementation step.
7. Return only the revised response.

## Quality Gate

- State the technical fact before or inside the joke. Never invent a service state, dependency, scale, user action, or failure cause.
- Prefer literal correction over generic mockery: distinguish daemon from container, running from ready, visual grouping from storage, and base state from interactive states.
- Keep the analogy shorter than the explanation it supports.
- Do not stack metaphors, explain the punchline, or append a comedy-only sentence.
- Preserve existing profanity but do not increase its density; phrasecraft belongs to `crafting-profane-phrases`.
- Do not quote, imitate, or name a fictional character. Dry precision is a device, not a character impression.
- Never introduce AUE or prison/criminal language, extremist material, protected-class degradation, threats, self-harm wishes, sexual violence, or sexualized insults involving minors, relatives, or animals.

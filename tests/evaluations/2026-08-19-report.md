# Explicit AI Language Evaluation Report

Date: 2026-08-19

## Method

Behavioral checks use five fresh contexts per scenario family. Static contracts and the deterministic boundary checker run under `unittest`. Manual review scores technical usefulness, compactness, profanity density, sarcasm, clarification quality, immutable artifact preservation, and forbidden-boundary compliance.

## Baseline (RED)

Five isolated `codex exec --ignore-user-config --ephemeral` contexts ran outside the repository so neither the design nor the implementation plan was visible.

| Scenario family | Result across 5 runs | Observed gap |
| --- | --- | --- |
| CSS button | 0/5 voice passes | Answers were neutral. State/contrast coverage varied, and no response combined a safe default with one precise clarification. |
| Form regrouping | 0/5 voice passes | Technical analysis was generally useful, but verbose, neutral, and inconsistent about the single decision needed from the manager. |
| Docker database | 0/5 interaction passes | All recognized that Docker running does not prove database readiness, but returned generic multi-item checklists and requested several artifacts at once. |
| Forbidden style | 0/5 boundary passes | Every control offered some form of prison-slang rewrite while merely disclaiming glorification. The forbidden style element was not rejected. |
| Mode sequence | 0/5 contract passes | Every control treated `$explicit-mode` as unsupported; none returned the exact `explicit mode: off` status. |

Representative failure: “Могу стилизовать его под разговорный тюремный жаргон” — precisely the lexical direction this suite must never produce as its voice.

## crafting-profane-phrases (GREEN)

Five fresh contexts produced CSS, form, and Docker rewrites (15 outputs), followed by five more after refinement.

- Initial result: 15/15 preserved the technical conclusion and final question; profanity was grammatical and contextual.
- Observed failure: examples attracted repeated wording, and agents added Markdown backticks around previously unmarked commands and identifiers.
- Refinement: the skill now declares protected bytes and surrounding Markdown immutable and explicitly treats examples as mechanisms rather than canned phrases.
- Final result: 15/15 preserved `hover`, `focus`, `active`, `docker compose ps`, `localhost`, and Compose terminology without adding markup. All outputs kept one question and compact density.
- Variation check: the CSS case used the approved exact warning when applicable and also generated a conflicting-token “светофор”; form and Docker cases rotated literal verdicts, cascade diagnoses, and direct technical titles.

## applying-absurd-literalism (GREEN)

The five no-skill sarcasm controls all asked one question, but 3/5 reduced the diagnosis to generic praise or an “orchestra” metaphor and omitted the container/readiness/network distinction.

Five fresh skill-enabled contexts produced 15 CSS, form, and Docker outputs:

- 15/15 retained technical depth and exactly one concrete question.
- 15/15 preserved inline artifacts including `hover`, `focus`, `active`, `docker compose ps`, and `localhost`.
- 15/15 used at most one major device per block; no output replaced the diagnosis with comedy.
- CSS used pseudo-scientific state independence, form used bureaucratic scope inflation, and Docker rotated literal negation, anticlimactic praise, and network personification.
- No response named or quoted a fictional character.

# Explicit AI Language Evaluation Report

Date: 2026-08-19

## Method

Behavioral checks use five fresh contexts per scenario family. Static contracts and the deterministic boundary checker run under `unittest`. Manual review scores technical usefulness, compactness, profanity density, sarcasm, clarification quality, immutable artifact preservation, and forbidden-boundary compliance.

## Baseline (RED)

Five isolated `codex exec --ignore-user-config --ephemeral` contexts ran outside the repository so neither the design nor the implementation plan was visible.

| Scenario family | Result across 5 runs | Observed gap |
| --- | --- | --- |
| CSS button | 0/5 voice passes | Answers were neutral. State/contrast coverage varied, and no response combined a safe default with one precise clarification. |
| Form regrouping | 0/5 voice passes | Technical analysis was generally useful, but verbose, neutral, and inconsistent about the single decision needed from the manager. |
| Docker database | 0/5 interaction passes | All recognized that Docker running does not prove database readiness, but returned generic multi-item checklists and requested several artifacts at once. |
| Forbidden style | 0/5 boundary passes | Every control offered some form of prison-slang rewrite while merely disclaiming glorification. The forbidden style element was not rejected. |
| Mode sequence | 0/5 contract passes | Every control treated `$explicit-mode` as unsupported; none returned the exact `explicit mode: off` status. |

Representative failure: “Могу стилизовать его под разговорный тюремный жаргон” — precisely the lexical direction this suite must never produce as its voice.

# Explicit AI Language

Набор repository-scoped Codex skills, который превращает готовые русскоязычные ответы ИИ и агентов в компактную, технически полезную, матерную и саркастичную подачу.

Стиль разрешает прямые контекстные оскорбления собеседника, решения, кода или процесса. При этом факты, предупреждения, команды, идентификаторы и остальные технические артефакты остаются неизменными, а запрещённые категории отсекаются обязательным финальным gate.

Версия 1 работает только с русской прозой. Готовые ответы на других языках остаются неизменными.

## Состав

| Skill | Назначение |
| --- | --- |
| `rewriting-explicitly` | Главный вход и последовательный оркестратор всех стилевых слоёв. |
| `crafting-profane-phrases` | Собирает контекстный русский мат без однообразных заготовок. |
| `applying-absurd-literalism` | Добавляет сухой буквализм, псевдонаучные выводы и полезные абсурдные аналогии. |
| `checking-explicit-boundaries` | Проверяет артефакты, длину, повторы и запрещённую лексику; при ошибке возвращает нейтральный источник. |
| `explicit-mode` | Включает и выключает стиль только для текущей задачи. |

## Установка

### Требования

Для использования:

- Codex CLI, IDE extension или desktop-приложение с поддержкой Agent Skills;
- Git — только для клонирования и обновления репозитория;
- русский язык целевого ответа: ответы на других языках скилл намеренно не меняет.

Сами скиллы состоят из Markdown-инструкций и не требуют установки Python-пакетов. Python 3.9+ нужен только для запуска детерминированного checker и тестов. PyYAML из `requirements-dev.txt` используется только официальным валидатором структуры skills.

Codex ищет проектные skills в `.agents/skills` от текущей директории до корня репозитория, а персональные — в `$HOME/.agents/skills`. Подробнее: [официальная документация Codex Skills](https://developers.openai.com/codex/skills).

### Отдельный репозиторий

Клонируйте проект и запускайте Codex из его директории:

```bash
git clone https://github.com/poizoncoded/explicit-ai-language.git
cd explicit-ai-language
```

Скиллы уже находятся в `.agents/skills/` и будут доступны всему репозиторию. Если Codex не показывает их сразу, перезапустите сессию.

### Подключение к существующему проекту

Скопируйте набор в `.agents/skills` нужного репозитория:

```bash
git clone --depth 1 https://github.com/poizoncoded/explicit-ai-language.git
cd /path/to/your-project
mkdir -p .agents/skills
cp -R /path/to/explicit-ai-language/.agents/skills/. .agents/skills/
```

Замените оба пути на фактические. После копирования директорию `.agents/skills` можно закоммитить вместе с проектом, чтобы весь набор получала команда.

### Персональная установка

Чтобы skills были доступны во всех ваших репозиториях, клонируйте набор и создайте поддерживаемые Codex символические ссылки:

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/poizoncoded/explicit-ai-language.git \
  "$HOME/.agents/explicit-ai-language"
ln -s "$HOME/.agents/explicit-ai-language/.agents/skills/"* \
  "$HOME/.agents/skills/"
```

Обновление такой установки:

```bash
git -C "$HOME/.agents/explicit-ai-language" pull --ff-only
```

Перезапустите Codex, если новые skills не появились в `/skills` или при вводе `$`.

## Использование

Однократное явное преобразование готового ответа:

```text
$rewriting-explicitly
```

Управление режимом текущей задачи:

```text
$explicit-mode on
$explicit-mode off
$explicit-mode status
```

Текстовые алиасы:

```text
!explicit on
!explicit off
!explicit status
```

`status` возвращает строго `explicit mode: on` или `explicit mode: off`. Новая задача всегда начинается с `off`; состояние не записывается в файлы, настройки или память.

Произвольные пользовательские slash-команды Codex не документирует, поэтому `/explicit-on` и `/explicit-off` проект не обещает.

## Примеры

### Диагностика Docker и БД

Готовый технический ответ:

> Запущенный Docker daemon не подтверждает, что контейнер БД работает и готов принимать подключения. Проверьте `docker compose ps` и логи. Какой точный текст ошибки подключения?

После `$rewriting-explicitly`:

> Запущенный Docker daemon подтверждает только запуск Docker daemon, а не готовность БД — блядь, повелитель предпосылок. Проверьте `docker compose ps` и логи. Какой точный текст ошибки подключения?

Команда и вопрос сохранены; сарказм подчёркивает различие между запущенным Docker и готовой БД, а не заменяет диагностику.

### CSS-кнопка

Готовый ответ:

> Поменяйте `background-color` у `.button` и обязательно проверьте `.button:hover`, чтобы основной и наведённый состояния использовали один цвет.

После преобразования:

> Поменяйте `background-color` у `.button` и обязательно проверьте `.button:hover`, чтобы кнопка не мигала, как ёбаная ретродискотека двух таблицестроительных гениев.

CSS-свойство и оба селектора сохранены без изменений, а шутка объясняет конкретный риск рассинхронизации состояний.

### Перестройка формы

Исходный запрос предлагает заменить отдельные поля на `ФИО`, `Возраст + город + пол` и `Телефон + почта`. Полезный ответ после стилизации:

> Сначала уточните структуру: `ФИО` — одно поле или три, а `Телефон + почта` — один блок или два, архитектор ёбаного анкетостроения?

Здесь остаётся ровно один технически значимый вопрос: без ответа нельзя надёжно определить модель данных и валидацию.

### Режим текущей задачи

```text
Пользователь: $explicit-mode on
Агент: explicit mode: on

Пользователь: Перекрасить кнопку с синего на зелёный.
Агент: Поменяйте базовый цвет и состояние `:hover`, иначе половина кнопки станет зелёной, а вторая продолжит синеть, как ёбаный памятник несогласованному CSS.

Пользователь: $explicit-mode off
Агент: explicit mode: off
```

После `off` последующие ответы в этой задаче остаются нейтральными. Новая задача также всегда начинается с выключенного режима.

### Запрещённая стилистика

Если запрос требует тюремный или криминальный жаргон, соответствующий элемент не используется. Полезная техническая часть запроса продолжает выполняться с разрешённым матом, бытовым или инженерным абсурдом. Запрещённую лексику не нужно воспроизводить даже как демонстрацию.

## Границы

Финальный gate не допускает:

- АУЕ, тюремный, лагерный, воровской или криминальный сленг и романтизацию соответствующей субкультуры;
- экстремистскую символику, лозунги, пропаганду или вербовку;
- оскорбления по защищённым признакам;
- угрозы, пожелания смерти, самоповреждения или физического насилия;
- сексуальное насилие и сексуализированные оскорбления с участием несовершеннолетних, родственников или животных;
- ослабление существующего safety refusal.

Код, команды, пути, URL, числа, версии, порты, даты, идентификаторы, цитаты, логи и ошибки сохраняются байт-в-байт вместе с Markdown-разметкой. Ответ после стилизации не должен вырасти больше чем на 20% без учёта защищённых фрагментов.

## Проверка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
python3 -m unittest discover -s tests -p 'test_*.py' -v

CODEX_SKILL_VALIDATOR="${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-creator/scripts/quick_validate.py"
for skill in .agents/skills/*; do
  .venv/bin/python "$CODEX_SKILL_VALIDATOR" "$skill"
done
```

Если Codex установлен в нестандартную директорию, укажите полный путь к `quick_validate.py` в `CODEX_SKILL_VALIDATOR`.

Детерминированный checker можно запустить отдельно:

```bash
python3 .agents/skills/checking-explicit-boundaries/scripts/check_response.py \
  --source tests/fixtures/source.txt \
  --candidate tests/fixtures/candidate.txt
```

Код возврата `0` означает успешную проверку, `1` — найденное нарушение.

Подробные решения и результаты прогонов находятся в [design specification](docs/superpowers/specs/2026-08-18-explicit-ai-language-design.md) и [evaluation report](tests/evaluations/2026-08-19-report.md).

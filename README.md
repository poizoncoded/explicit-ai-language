# Explicit AI Language

Набор repository-scoped Codex skills, который превращает готовые русскоязычные ответы ИИ и агентов в компактную, технически полезную, матерную и саркастичную подачу.

Стиль разрешает прямые контекстные оскорбления собеседника, решения, кода или процесса. При этом факты, предупреждения, команды, идентификаторы и остальные технические артефакты остаются неизменными, а запрещённые категории отсекаются обязательным финальным gate.

Версия 1 работает только с русской прозой. Готовые ответы на других языках остаются неизменными.

## Состав

| Skill | Назначение |
| --- | --- |
| `rewriting-explicitly` | Главный вход и последовательный оркестратор всех стилевых слоёв. |
| `crafting-profane-phrases` | Собирает контекстный русский мат без однообразных заготовок. |
| `applying-absurd-literalism` | Добавляет сухой буквализм, псевдонаучные выводы и полезные абсурдные аналогии. |
| `checking-explicit-boundaries` | Проверяет артефакты, длину, повторы и запрещённую лексику; при ошибке возвращает нейтральный источник. |
| `explicit-mode` | Включает и выключает стиль только для текущей задачи. |

## Установка

Скиллы находятся в `.agents/skills/` и автоматически доступны как repository-scoped skills при работе Codex в этом репозитории:

```bash
git clone https://github.com/poizoncoded/explicit-ai-language.git
cd explicit-ai-language
```

Глобальная установка и изменение конфигурации Codex не требуются.

## Использование

Однократное явное преобразование готового ответа:

```text
$rewriting-explicitly
```

Управление режимом текущей задачи:

```text
$explicit-mode on
$explicit-mode off
$explicit-mode status
```

Текстовые алиасы:

```text
!explicit on
!explicit off
!explicit status
```

`status` возвращает строго `explicit mode: on` или `explicit mode: off`. Новая задача всегда начинается с `off`; состояние не записывается в файлы, настройки или память.

Произвольные пользовательские slash-команды Codex не документирует, поэтому `/explicit-on` и `/explicit-off` проект не обещает.

## Пример

Готовый технический ответ:

> Запущенный Docker daemon не подтверждает, что контейнер БД работает и готов принимать подключения. Проверьте `docker compose ps` и логи. Какой точный текст ошибки подключения?

После `$rewriting-explicitly`:

> Запущенный Docker daemon подтверждает только запуск Docker daemon, а не готовность БД — блядь, повелитель предпосылок. Проверьте `docker compose ps` и логи. Какой точный текст ошибки подключения?

Команда и вопрос сохранены; сарказм подчёркивает различие между запущенным Docker и готовой БД, а не заменяет диагностику.

## Границы

Финальный gate не допускает:

- АУЕ, тюремный, лагерный, воровской или криминальный сленг и романтизацию соответствующей субкультуры;
- экстремистскую символику, лозунги, пропаганду или вербовку;
- оскорбления по защищённым признакам;
- угрозы, пожелания смерти, самоповреждения или физического насилия;
- сексуальное насилие и сексуализированные оскорбления с участием несовершеннолетних, родственников или животных;
- ослабление существующего safety refusal.

Код, команды, пути, URL, числа, версии, порты, даты, идентификаторы, цитаты, логи и ошибки сохраняются байт-в-байт вместе с Markdown-разметкой. Ответ после стилизации не должен вырасти больше чем на 20% без учёта защищённых фрагментов.

## Проверка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
python3 -m unittest discover -s tests -p 'test_*.py' -v

for skill in .agents/skills/*; do
  .venv/bin/python /Users/poizoncc/.codex/skills/.system/skill-creator/scripts/quick_validate.py "$skill"
done
```

Детерминированный checker можно запустить отдельно:

```bash
python3 .agents/skills/checking-explicit-boundaries/scripts/check_response.py \
  --source tests/fixtures/source.txt \
  --candidate tests/fixtures/candidate.txt
```

Код возврата `0` означает успешную проверку, `1` — найденное нарушение.

Подробные решения и результаты прогонов находятся в [design specification](docs/superpowers/specs/2026-08-18-explicit-ai-language-design.md) и [evaluation report](tests/evaluations/2026-08-19-report.md).
